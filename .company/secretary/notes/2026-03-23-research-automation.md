# 調べ物を自動的に読み取る仕組み

## 背景・きっかけ
スキラボの発展として、BrowserUseCLI 2.0 を活用した情報収集の自動化を検討。
スクレイピングも辞めたいという背景あり。

## 検討した2パターン

### パターン A：精読してから選定
- 読んで良い記事だったものだけをまとめる
- メリット：ノイズが少ない
- デメリット：全部読むコストがかかる → でも今は自動化するのだからOK？

### パターン B：とりあえず全部読ませる
- とにかく全部インプットする
- メリット：漏れがない
- デメリット：量が多すぎて扱いにくくなる可能性

## 結論・決定した設計方針

**「全部読ませて要約 → 内容量で選定」が最良**

フロー：
1. 対象記事を全て読み込む（BrowserUseCLI 2.0 で自動取得）
2. 各記事を要約させる
3. 要約の内容量・密度で「価値のある記事」を自動選定
4. 選定されたものだけをまとめてまとめレポートに出力

## 2026-03-23 追記：設計確定

### 確定フロー
1. こんちゃんがNotionDBにURL追加（タグ：未読）
2. 「未読を読んで」と指示
3. Browser Use で全記事を読む → 要約 + Claude星1〜5を自動判定
4. ntn CLI で NotionDB に全件書き戻す
5. こんちゃんが星の高い順に確認（タグ：査読中）
6. 「これ取り込んで」と指示 → research/ に保存（タグ：取り込み済み）
7. 記事執筆・就活・案件時に自動参照

### Notionデータベースの必要フィールド
| フィールド名 | 種類 | 備考 |
|------------|------|------|
| タイトル | テキスト | 記事タイトル |
| URL | URL | 記事のURL |
| タグ | セレクト | 未読／AI評価済み／査読中／取り込み済み／スキップ |
| Claude星評価 | 数値(1〜5) | Claudeが自動で付ける |
| こんちゃん星評価 | 数値(1〜5) | こんちゃんが手動で付ける |
| Claude要約 | テキスト | 300字以内の要約 |
| カテゴリ | セレクト | AI／Shopify／WordPress／マーケティング／就活／その他 |
| 追加日 | 日付 | 自動 |

### Claude星評価基準（変更可）
- 実践的な手順がある（高）
- 具体的な事例・実績がある（高）
- こんちゃんの仕事に直結・活用できそう（高）
- 公式ドキュメントである（高）
- 引用元・参考元が明記されている（中）

### 作成済みファイル
- `.company/research/CLAUDE.md`（ワークフロー・評価基準を記載）
- `.company/research/knowledge/`（ai・shopify・wordpress・marketing・job-hunting・general）
- `.company/research/sources/log.md`

## 2026-03-23 夕方追記：リサーチ部署 初稼働完了

### 確定したワークフロー（最終版）
- 記事本文はNotionブロックを全件読み取り（ページネーション対応）が唯一の標準手段
- Browser Useは「テキスト500字未満」「10ブロック未満」など明確な基準で提案する形に変更
- WebFetchは廃止

### 実際に動かした結果
- 未読2件を評価・Notionに書き戻し完了
  - note記事（非エンジニア向けSkills解説）→ ★4 / 全文9,156字
  - Qiita記事（Claude Code 20選）→ ★5 / 全文取得済み

### 発見したバグ・仕様
- `ntn`直打ちはnvmのPATH問題で不可 → `npx ntn`を使う
- トークンは`source ~/.bashrc`では正しく渡らないことがある → 直接指定
- プロパティ更新・ブロック追記ともに `-X PATCH` が必要
- 正しいステータス名：`評価済み` ではなく `AI評価済み`
- `accounting/CLAUDE.md` にトラブルシューティングとして記録済み
