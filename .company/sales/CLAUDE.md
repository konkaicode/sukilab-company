# 営業部署

## 役割
Web制作フリーランスとしての営業活動を管理する。
募集文と応募文をセットで蓄積し、**営業プロフィールDB（profile/）を土台に応募文を半自動生成**する。
将来的には新規募集の自動探索（sources.md）も担う。

## フォルダ構成
- `profile/` — 営業プロフィールDB（応募文生成の土台。下記参照）
- `cases/` — 案件ごとの応募セット（募集文 + 応募文 + メモ）
- `templates/` — 応募文の骨格テンプレ（型）
- `sources.md` — ②新規募集の自動探索の設計（実装は次マイルストーン）
- `log.md` — 営業履歴（日付・媒体・結果）

### profile/（営業プロフィールDB）
| ファイル | 内容 |
|---------|------|
| `basics.md` | 不変の自己紹介素材（氏名・経歴・ポートフォリオURL・連絡先・実績件数の標準表記） |
| `works.md` | 制作実績カタログ（タグ付き）＋ 募集タイプ別おすすめ実績の早見表 |
| `strengths.md` | こだわり・強み・差別化（応募文のトーン作り） |
| `conditions.md` | スキル・対応範囲・単価感・稼働条件・NG（マッチング判定基準） |

### templates/（応募文の型）
| ファイル | 使う場面 |
|---------|---------|
| `pitch-free.md` | 募集側が回答形式を指定していない（自由文） |
| `pitch-numbered.md` | 募集側が「応募時に必要な内容」を①②③…と項目指定している |

## ケース命名規則
`NNN-識別名/` — 例: `001-haniwaman`

## 各ケースのファイル
- `listing.md` — 相手の募集文
- `pitch.md` — 自分の応募文
- `memo.md` — 結果・気づき・メモ（任意）

## ログ形式
```
| 日付 | 案件番号 | 相手 | 媒体 | 結果 |
```
- 結果: 受注 / 不採用 / 未返信 / 選考中 / 見送り

## ①応募文の半自動生成ワークフロー

こんちゃんが募集文を渡して「応募文作って」と言ったら、以下のSTEPで下書きを生成する。
**生成はClaudeが行い、最後は必ずこんちゃんがレビュー**する（半自動）。

### STEP 1：募集文を保存
- 次の案件番号でケースフォルダを作成：`cases/NNN-識別名/`
- 募集文を `listing.md` に保存（媒体・送付先も記載）

### STEP 2：募集文を解析
募集文から以下を抽出する:
- **媒体・送付先**（コミュニティDM / メール / フォーム 等）
- **必須条件・歓迎条件**（技術・経験年数・実績数など）
- **求める人物像**（スピード重視／品質重視／長期／AI活用 等）
- **単価感**（提示があれば）
- **応募フォーマット**：自由文か、①②③の項目指定か → 使うテンプレを決める
- **業種・サイト種別**（コーポレート / LP / EC / リニューアル / Shopify 等）

### STEP 3：profile/ を読み、実績を選定
- `profile/basics.md`・`conditions.md`・`strengths.md` を読み込む
- `profile/works.md` の `タグ` と「募集タイプ別おすすめ早見表」を使い、
  募集条件にマッチする実績を**上位3件**選ぶ
  - 優先度：技術/業種の一致 > 公開URLあり > 直近

### STEP 4：応募文の型を決定
- STEP2のフォーマット判定に従い `templates/pitch-numbered.md` か `pitch-free.md` を選ぶ
- 番号指定の場合は**募集側の項目名・順番・記号をそのまま踏襲**する

### STEP 5：pitch.md 下書きを生成
- 選んだテンプレの `{{ }}` を profile/ のデータで埋める
- `strengths.md` の「応募文での使い分けメモ」を見て、相手に刺さる強みを強調
- 文体は既存 `cases/*/pitch.md` をお手本にする（こんちゃんらしい丁寧で前向きなトーン）
- `cases/NNN-識別名/pitch.md` に保存

### STEP 6：根拠メモを添えて提示 → レビュー → ログ
- 提示時に**「なぜこの3実績を選んだか」「何を強調したか」**を一言添える
- こんちゃんの修正を反映
- `log.md` に1行追記（日付・案件番号・相手・媒体・結果=選考中等）

## ②新規募集の自動探索
- 設計は `sources.md` を参照（実装は次マイルストーン）
- 対象チャネル：求人・スカウト系 / X検索 / Slackコミュニティ
- マッチング基準は `profile/conditions.md` を再利用
- 見つけた募集はマッチ度★付きで提示 → 気になるものは①にそのまま流す

---

## メンテナンス
- 新しい実績ができたら `profile/works.md` に追記（タグも付ける）
- 単価・稼働条件が変わったら `profile/conditions.md` を更新
- 「こだわり」の具体エピソードは壁打ちで `profile/strengths.md` に追記
- profile/ を直せば全応募文の元ネタが更新される（pitch への重複コピペをしない）
