# ②新規募集の自動探索 — 設計

> ⚠️ これは**設計ドキュメント**。実装は次の段階。
> 指定チャネルを巡回し、こんちゃんに合う新規募集を見つけてマッチ度付きで提示する仕組み。
> マッチング判定の基準は `profile/conditions.md` を再利用する。

## 全体フロー（将来像）

```
[対象チャネル巡回] → [募集を抽出] → [conditions.md と照合・スコアリング]
   → [マッチ度★付きで sales/inbox/YYYY-MM-DD.md に出力] → [気になる募集を①応募文生成へ]
```

## 対象チャネル（こんちゃんが選択：求人・スカウト系 / X検索 / Slackコミュニティ）

| チャネル | 取得手段 | 難易度 | 備考 |
|---------|---------|--------|------|
| 求人・スカウト系（Wantedly 等） | WebFetch 中心（必要なら Browser Use） | 中 | 公開求人ページが拾える。リモートWeb制作で絞る |
| X（SNS）検索 | WebFetch / Browser Use | 中 | こんちゃんの主要チャネルの一つ。下記キーワードで巡回 |
| コミュニティ（Slack：デイトラ / RyoHack） | Browser Use（CDP接続必須） | **高** | ログイン壁あり。自動化は難。**当面は手動運用**も現実的 |

### Browser Use の前提（メモリ feedback_browser_use_cdp）
- CDP接続が必須。こんちゃんが先にデバッグモード Chrome を起動 → 私が `--connect` で接続する
- WSL ではなく Windows ネイティブ運用なので、起動コマンドは別途確認

## 検索キーワード案（X・求人サイト共通の出発点）

- `WordPress 制作 募集` / `コーダー 募集` / `LP コーディング 募集`
- `Web制作 業務委託 リモート` / `フロントエンド 副業 リモート`
- `Shopify 構築 募集`
- `#コーダー募集` `#Web制作 #募集`（X のハッシュタグ）
- 除外したい語：常駐 / 出社必須 / 早朝 / 単純作業大量（conditions.md の NG に基づく）

## マッチング・スコアリング（conditions.md 再利用）

各募集を以下で採点し、★1〜5でランク付け:

| 評価軸 | 加点 |
|--------|------|
| 技術が合致（WordPress / LP / GSAP / Shopify） | 高 |
| リモート・業務委託・稼働20〜30h に収まる | 高 |
| 単価が目安（LP 8万〜 等）以上 or 妥当 | 中 |
| 業種・実績との親和性（works.md のタグと一致） | 中 |
| NG条件（常駐・早朝・単純作業大量）に該当 | 減点・除外 |

## 出力フォーマット（`sales/inbox/YYYY-MM-DD.md` に新設予定）

```markdown
## {媒体} — {募集タイトル}
- URL / 連絡先: ...
- マッチ度: ★★★★☆
- 合致理由: WordPress＋リモート＋単価妥当
- 懸念: 稼働40h希望（要確認）
- おすすめ実績（①に渡す用）: ドローン塾 / 恒電社 / SUN
- アクション: [ ] 応募文を作る / [ ] スルー
```
